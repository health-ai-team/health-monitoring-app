# Architecture and Technical Decision Log

## 1. Purpose

This document records important project decisions so that team members and Freebuff agents do not repeatedly reconsider or contradict previously approved decisions.

It prevents:

- Repeated debates
- Conflicting implementations
- Different AI agents making different architectural assumptions
- Forgotten decisions
- Technology drift

This is not a general project specification.

Detailed rules belong in the appropriate core document.

---

## 2. Decision Format

Each decision should use:

### Decision ID

`DEC-XXX`

### Date

`YYYY-MM-DD`

### Decision

What was decided?

### Context

Why was a decision needed?

### Options Considered

What alternatives were considered?

### Chosen Option

What was selected?

### Reason

Why was it selected?

### Affected Documents

List affected documents.

### Affected Workstreams

AI / Frontend / Backend

### Status

PROPOSED / APPROVED / SUPERSEDED

### Approved By

List team members or team decision.

---

## 3. Initial Decisions

### DEC-001 — Gemma 4 as Primary AI Model

Status: APPROVED

Decision:

Gemma 4 is the approved primary AI model for the application.

Reason:

The project is required to use Gemma 4 and will leverage its relevant capabilities for:

- Longitudinal context understanding
- Natural-language health interaction
- Context-aware responses
- Candidate structured data extraction
- Summarization
- Controlled tool use
- Multilingual interaction where validated
- Multimodal functionality where validated and approved

The team must not claim medical superiority without evidence.

Detailed AI behavior belongs in `06_AI_SPECIFICATION.md`.

---

### DEC-002 — GitHub as Source of Truth

Status: APPROVED

Decision:

GitHub is the source of truth for application code and shared project documentation.

Reason:

All team members and Freebuff workspaces must operate against a common version-controlled project state.

---

### DEC-003 — Three Workstreams

Status: APPROVED

Decision:

The project is divided into:

- AI / Gemma 4
- Frontend
- Backend / Data

Reason:

This division reduces conflicting edits and gives each team member clear ownership.

Detailed responsibilities are defined in `03_TEAM_WORKFLOW.md`.

---

### DEC-004 — Deterministic Safety Alerts

Status: APPROVED

Decision:

Critical safety alerts must be generated by deterministic backend rules rather than free-form AI judgment.

Reason:

Gemma 4 must not independently decide that a dangerous medical threshold has been crossed or trigger critical emergency alerts.

Exact thresholds must be explicitly approved before implementation.

---

### DEC-005 — Centralized Data Storage

Status: APPROVED

Decision:

Patient health data, daily survey responses, and AI chat conversations are stored in a central database.

Reason:

The same underlying data foundation supports:

- Patient history
- Patient trends
- Doctor charts
- Doctor summaries
- AI context retrieval

Storage does not mean all data is automatically sent to Gemma 4.

---

### DEC-006 — Backend-Controlled AI Data Access

Status: APPROVED

Decision:

Gemma 4 does not directly access the database.

The backend retrieves authorized relevant context and provides it to the AI.

Reason:

This maintains authorization, privacy, data minimization, and security boundaries.

---

### DEC-007 — AI-Extracted Data Requires Validation

Status: APPROVED

Decision:

Health information identified by Gemma 4 from natural-language conversations is treated as candidate structured data.

Backend validation is required before persistence.

Reason:

AI output may be incomplete, ambiguous, or incorrect.

---

## 4. Rule for New Decisions

When a major decision is made:

1. Record it here.
2. Update the relevant specification.
3. Notify affected workstreams.
4. Ensure Freebuff agents can see the decision.
5. Do not leave conflicting old documentation active.

---

## 5. Superseded Decisions

When a decision changes:

- Mark the old decision `SUPERSEDED`.
- Record the new decision.
- Update affected documents.
- Explain what changed.
